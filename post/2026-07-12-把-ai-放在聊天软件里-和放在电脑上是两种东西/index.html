在手机上和电脑上的 Agent 聊天之后，我就不用去电脑前了

我每天早上和晚上都用小爱同学播英文歌，给小孩做英语熏听。孩子不懂这门语言，但多听总归有好处——这个群里刷过不少，大家基本都这么说。

但小爱同学经常不靠谱。有时候没播，有时候播一半停了。

之前发现不对劲，我只能走到电脑前，在终端里看脚本出了什么问题，改代码，重新跑。

几次之后我就放弃了。不听就不听吧。

但想想孩子还小……算了还是修吧。等到下次出问题，又重复一遍这条路。然后又放弃了。

后来我把电脑上管小爱同学的 Agent 接进了飞书——我说的话会通过飞书机器人传到它那里。

变化不是"方便了一点"，是完全不一样了。

现在发现歌没播，我打开手机飞书，给 Agent 发条消息：「去查一下小爱同学为啥没播，修好它。」它在电脑上查日志，过一会儿告诉我原因，然后自己修好重新跑——比如判断是任务没触发就重新调度，进程挂了就重启，配置错了就修正。

同样的问题，同样的难度。我的态度从"算了不搞了"变成了"让我看看"。

差别在反馈链路

原来的流程：起身 → 走到电脑前 → 开终端 → 查日志 → 改代码 → 重跑。

这一串动作，在脑子里的成本不是加法，是乘法。光是想到"又要去电脑前搞"，就足以劝退我。

而现在，我只需要在手机上发句话。真正降下来的不是修复耗时——该查日志还是查、该改配置还是改——而是我发起修复的成本：从"起身去电脑前"变成了"说句话就开始了"。

这不只是换个界面的事。通过手机飞书跟电脑上的 Agent 聊天，看起来只是换了个沟通方式，但它改变的是我的意愿阈值。

一件事的修正成本越低，你就越愿意去修。原来我容忍"出错了就放着"，现在出问题了直接说一声就好。

这种意愿变化不只是影响"出错修不修"——它连带改变了你跟 Agent 的互动频率。原来 Agent 在电脑上跑完就完了，日志刷过去，我隔一两个小时才想起去瞄一眼，卡住半天都不知道。现在 Agent 跑完了直接往飞书群里汇报，我余光扫一眼就知道进度，有问题直接语音说一句。

频率变了，信息的获取方式就变了。

中断式工作 vs 轮询式工作

还有一个点。

我工作经常被打断——家里有小孩，没办法连续几小时深度聚焦。但我做的事多数是"派一个任务出去，等它跑完，再派下一个"。这种多任务轮询模式，很适合放进飞书这类即时通讯工具来管——不用守在电脑前，手机扫一眼就行。

没有接进飞书之前，我需要定期去电脑前看看 Agent 卡住了没有。这本身就是一个心智负担——你得"记得去检查"。接进来之后，Agent 跑完了会主动发消息过来，出问题了在手机上直接让 Agent 处理。

我不用再记着去看了。Agent 自己会来找我。

回到小爱同学

现在这套播放任务稳定跑了快一个月了——之前要手动维护的时候，每次一坏我就放弃，最多坚持两天。

举个真实的例子：有天晚上歌又没播，我发了句话「去看看怎么回事」。Agent 查完日志发现是进程挂了，自动重启后补播了一首。全程我就在沙发上躺着。

能跑下去，不是因为我突然有耐心了，而是因为出问题之后，我只需要在手机上发句话。有些事自己用可以忍，给孩子用的，不能忍。这个差别，决定了你到底是天天跑去电脑前修脚本，还是远程聊几句就搞定了。

如果你也有类似的情况——电脑上跑了些任务需要时不时看一眼——试试把它们接进飞书，通过手机跟电脑上的 Agent 聊天。反馈链路一短，你会发现一切都不一样了。

反正也不费电。主要是费手机电量——和一个忍你自言自语的老婆。
