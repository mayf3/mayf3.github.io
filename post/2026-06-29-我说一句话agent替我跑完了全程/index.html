我说一句话，Agent 替我跑完了全程

我宝宝说想折纸。

我给我家 Agent 发了一句话，让它帮忙搞折纸的材料。它自己搜好了教程，把折纸指南和打印用的纸放在一起打印了出来。后来我想换一种颜色，又跟它说了一句，它重新搞好了。

从他说"想折纸"到他拿到纸，不到五分钟。

那一刻我感觉，被改变的可能不只是效率。

被消灭的"中间步骤"

折纸不是个例。最近我发现，Agent 在我生活里干掉最多的东西，是"中间步骤"。

摆摊采购。 以前收到摆摊要用的物资信息，事情比较零散。现在整个流程串起来了：信息进来，自动加到购物清单助手（我的另一个 Agent）里，相关物资已经在购物车里等着了。

两个场景，模式一样：以前是你做 N 步拿到结果，现在你做 1 步——说"我要"。

我管被干掉的那 N-1 步叫中间管理成本。

中间管理成本是什么

不是钱。是你的注意力和决策次数。

每次你打开搜索框、筛选结果、对比选项、做决定——你的注意力都在被消耗。单次不多，但一天累加起来，你会觉得"好累但好像也没干什么"。这就是中间管理成本的隐性伤害。

传统工具的逻辑是：我给你更好的工具，你自己来。更好的搜索引擎、更快的打印机、更方便的购物 App。但工具再好，你还是那个在中间跑来跑去的人。

Agent 的逻辑是：你说要什么，我来跑。

从人适应工具，变成了工具适应人。

但这跟自动化有什么区别？

好问题。因为自动化的本质也是"你只管说，机器来做"。

我这里说的传统自动化，主要是提前写好的规则：如果收到消息包含"摆摊"，就执行脚本 A。我让龙虾搞折纸的时候，它不是在执行一个叫"折纸流程"的脚本，而是识别了"小孩要折纸"这个请求意图，自己去搜索材料并打印出来。在我的系统里，Skill 是手脚——搜索、打印、加购物车，它们负责动作；Agent 负责判断调不调用。Agent 在上面加了一层角色定位、领域记忆和对任务对错的经验积累。

真正让我想继续验证的是：当任务从折纸换成别的东西，它能不能临时组合现有工具，而不是等我重新写一条流程。

代价呢？烧 token。每一次理解、判断、决策都在消耗 token，这比执行预设脚本更贵。但你换来的是——你只需要做一个决定：知道自己要什么。

我在赌的方向

回到开头。宝宝说想折纸，我只给 Agent 发了一句话。

这可能是我对 Agent 最大的赌注：中间步骤会被消灭，“我要"会成为新的交互界面。
