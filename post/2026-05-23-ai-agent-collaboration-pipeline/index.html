现在写文章，我只做两件事

录随想，审稿。最后确认发布。

录随想是录一段语音。审稿是在飞书文档里看完成型的文章，逐段评论。确认发布是最后点一下。除此之外的活，选题、写稿、审阅、发布，都被一组 AI Agent 接走了。

我管这套流程叫"内容协作流水线"。它不是全自动的，是半自动的。

以前不是没有想法，是没有足够精力把想法变成稳定发布的文章。想写的东西攒了一堆，真要坐下来从零写到尾，光想想就累了。现在这套流程把成本压下来了，我才真正开始写。

到目前为止发了三篇，这篇是第四篇。这篇文章本身也是这条流水线的产物。

跑步时的灵感，完整记录下来

我有通过跑步思考问题的习惯。复杂问题在跑步的时候容易想清楚，灵感也经常在那个时候爆发。

跑步时想到什么，我会用豆包输入法。按一下进入语音模式，说一段，再按一下取消。有时候一条，有时候一口气录十几条。

这些录下来的东西我叫"随想"。不是正式笔记，不是大纲，就是脑子里冒出来的东西。有观点，有情绪，有例子，也有废话。

我把这些语音文字发给"随想记录员"。它是一个专门的 Agent，工作很简单：完整原样地把内容记录下来。不整理，不压缩，不评价。就是忠实保存。

为什么要专门调教一个"只记录不给建议"的 Agent？因为默认的 LLM 会忍不住给建议。有一次我吐槽说"今天代码写得特别顺"，随想记录员没忍住，在后面加了一句"建议你记录一下这次顺利的原因，以后可以复现"。我当场就炸了。我要的是记录，不是建议。我把这条规则加到 prompt 里：只记录，不评价，不给建议。后来就没再犯过。就是这类小细节，每个 Agent 都需要单独调教。

它有个做法我比较在意。记录完之后，它会回复我：总字数是多少，前 100 个字符是什么，后 100 个字符是什么，输出目录在哪。这样我能确认它真的记清楚了，不是假装记了其实没记。这个验证机制很重要，不然我后面写稿的时候发现内容丢失就晚了。

从随想到成文：我没参与

随想记录员记录完之后，后面的事全是自动的。

写作 Agent 有每天定时任务，会自动去拉取随想记录，分析哪些素材可以写成文章、应该拆成几篇、每篇核心内容是什么。然后直接开写，写完发到本地的文章管理平台。

我看到的就是最终成型的文章。中间不会来问我"这篇要不要写"“那个选题好不好”。

写作 Agent 还有个习惯：每天定时去学习怎么更好地写文章。它回顾之前的审稿意见，看哪些问题反复出现，然后改进自己的写作。算是留了一个自我迭代的口子。

这个阶段出来的文章质量参差不齐，但我不在初稿阶段介入。真正决定质量的是后面的审稿循环。

审稿：三轮之后才飞书

审稿环节我搭了一条夜间自动流水线（详见另文《夜间自动审稿流水线》）。

简单说就是：每天晚上自动审一轮，文风分析师给意见，写作 Agent 改，改完再审。三轮之后才上传飞书文档给我看。

审稿的核心是多模型双视角：文风分析师自己审一遍，然后让 ChatGPT 也重写一份作为参考。不同模型的关注点不一样，ChatGPT 的版本可以帮写作 Agent 跳出固定的写法。

三个轮次审完之后，文章状态变成"待确认"，这时候才上传飞书。

飞书文档：到我出场了

文章管理平台里审了三轮之后，才上传飞书文档。前几轮审稿都在本地完成，飞书只在作者亲自介入时用。

我在飞书里评论。不分开手机和电脑，手机上看整体感受，电脑上做大幅调整。看到哪段不舒服，直接在文档里点评论。审完之后，让文风分析师自己去飞书里拿评论结果。

一篇文章从初稿到我最终确认，大概需要一个星期。主要是因为我实在没有时间专门躺下来审稿，只能在碎片时间里看。大部分等待时间花在我身上，不是花在 Agent 处理上。

发布：持续进化的工程活

发布环节有个专门的 Agent，叫"发布管家"。它负责控制浏览器，像人一样操作网页：打开平台、登录、粘贴内容、上传图片、点击发布。

一开始每个平台都要跟发布管家来回交流，让它不断尝试，我也会去看发布效果。后来我让它也变成定时任务：每天晚上捞一下哪些文章还没发，然后一晚上连着 7 个小时持续往各平台发。一篇文章现在能发到十几个平台，中文的英文的都有。

发布管家有个特别的地方：它会自我进化。每次发布后，它会自己修改发布的 skill，主要是改 reference 文件。每个平台一个 reference，记录那个平台的怪癖和操作流程。发得越多，它对每个平台越熟。

这件事远不如看起来那么稳定。浏览器自动化面对的不是固定 API，而是随时可能变化的网页界面。第一篇在微信公众号发布时，就遇到一个大坑：代码块全部变成了普通文本，缩进全乱，图片被压缩到看不清。我花了半小时手动修复。后来发现是微信公众号的 Markdown 解析器对代码块的支持很差，发布管家记住了这个坑，每次发之前自动检查代码块格式，如果不行就转换成纯文本加格式标签。

还有更玄的。有的平台三天两头踢出登录，必须重新扫码；有的平台必须指定封面图，尺寸不对就拒绝发布；有的平台 Markdown 表格渲染不出来，得转成图片。发布管家能省很多时间，但还不能完全无人值守。

发布完之后，发布管家会记录每篇文章在每个平台的链接，自己打开发布后的页面检查排版效果。我也会去看一眼。

几篇文章暴露的问题

这篇是第四篇。回顾这几篇的经历，有几个真实的问题。

Agent 生成的初稿经常有事实错误，编造没发生过的事、夸大数字、搞错流程。每篇都会遇到。这个问题只能靠多轮审稿加我亲自审来兜底。

审稿意见要沉淀。如果只说"帮我审稿"，Agent 会给一堆放哪都能用的建议。后来我把审稿标准写得很细：专门检查逻辑跳跃、AI 腔、空泛表达、事实准确性。文风分析师也维护着关于我风格的 skill，审得越多越准。

版本要系统化。前期靠文件目录结构规范，后来做了专门的写作发布平台来管理文章状态和版本。文章改几轮之后很容易乱，必须有一套系统。

发布自动化最脆弱。浏览器控制、平台 UI、登录态、预览检查，每一项都可能出问题。发布管家能省很多时间，但还不能完全无人值守。

写在最后

这套流程的核心价值就一个：把成本压下来。

以前不是没想法，是从想法到文章到发布，成本太高了。光是坐在电脑前从零写起这一件事，就能把写文章的念头打消掉。现在龙虾（就是我的写作 Agent）把流程拆开、编排、自动化，还持续迭代优化。我只需要动动嘴皮子记录想法，重点花时间在飞书里审稿评论，改到满意，系统自动发布。

龙虾每天还在学习怎么写得更好。文风分析师的审稿 skill 在持续沉淀。发布管家的平台 reference 在不断更新。这些东西都在迭代，不是一次搭好就完事的。

写于 2026 年 5 月。这篇文章本身，就是这条流水线的产物。
